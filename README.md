# 统计看板 · Usage Dashboard

整个 DSH 的 Token 账本：左侧边栏一个柱状图标，点开是一张分析台。

## 页面结构

自上而下：

1. **吸顶工具条** — 标题与统计区间、区间切换（全部 / 今天 / 7 / 30 / 90 天）、刷新。整页滚动时始终可见。
2. **四个数字** — 预估花费（含缓存省下的钱与倍数）、Tokens 构成（输入 / 缓存读 / 输出的比例条与绝对值）、缓存命中率、调用次数（会话数、子代理数、均摊每次花费）。
3. **左列**
   - **每日花费** — 每根柱子按「高峰 / 空闲」堆叠，虚线为日均；可切「Tokens」看输入 / 缓存 / 输出。带 y 轴刻度。
     区间落到**单日**时自动切换为**分时**（00:00–23:00），标题变为「今日分时花费」，否则一天只会有一根柱子。
   - **使用节奏** — 周一–周日 × 24 小时热力网格，格子颜色是 tokens 量级，琥珀色标出真正按高峰计价的格子（周末即使在同一钟点也是空闲价）。
4. **右列**
   - **花费排行** — 按花费（不是 tokens）排序，可在服务商 / 模型 / 会话 / 目录之间切换，每行带占比。
   - **峰谷占比** — 高峰与空闲的花费拆分，并给出一句结论：高峰 token 占多少、却贡献了多少花费。
5. **运行性能** 与 **工具使用** — 沿用 ZCode 的 per-call 口径：
   - 运行性能：平均延迟（step 起点到 assistant 消息的时间差）、最慢一次、输出速度（tokens/秒）、推理 token 占比、中断调用数，并给出可测样本数。
   - 工具使用：工具调用总次数、平均耗时、出错率、含工具调用的请求占比，以及按工具名的次数排行。
6. **模型用量** — 多模型曲线图，每条线是一个模型按天的 token 量。区间跟随顶部控件；右上「模型」下拉可勾选任意几个模型对比（默认显示用量前三）。可切 Tokens / 占比 / 花费；图例也可点击开关；悬停竖线读出当天各模型的数值。

## 悬浮提示

每个图表都有就地悬浮读数，不是浏览器原生 `title`：

- **每日柱**：日期、高峰/空闲花费、输入/缓存/输出三段、合计、调用次数
- **使用节奏**：星期与小时、该格 tokens、占当天比例、是否高峰价
- **花费排行**：名称、花费与占比、调用次数、tokens，目录/会话类还会给出完整路径
- **峰谷占比**：高峰与空闲各自的金额、tokens、调用次数
- **模型曲线**：当天的日期，以及当天真正有调用的模型（零值不列出，按用量降序）、合计

提示框跟随鼠标，靠近视口右/下边缘时自动翻转，`position: fixed` 渲染所以不会被滚动容器裁掉。

## 数据从哪来

唯一的真相来源是会话日志：每条 `assistant/message` 事件都带有 `usage`
（`inputTokens` / `outputTokens` / `cacheReadTokens` / `cacheWriteTokens` / `reasoningTokens`）
以及 `provider` + `model`。Host 半通过 `sessionQuery` 列出全部会话（含子代理、工作流、
已归档会话），逐个 replay 折叠成一次调用的记录。

- 统计范围覆盖整个 profile 的全部会话，子代理会话在会话列单独标记。
- fork 出来的会话会重放父会话的历史前缀，这部分**不会**被重复计费（按
  `inheritedEventCount` 跳过）。
- `inputTokens` 不包含缓存读写，四类相加才是总消耗（与 DSH 自身的
  `totalTokens` 口径一致）。

模型曲线按**模型名**聚合，不是按 `provider/model`：同一个模型经多个中转（`cn:`、
`wb:cn:`、`global:` 等路由前缀）只画一条线，原始模型名保留在 `variants` 里。
返回用量前 40 个模型（面板默认只画前三个，其余由模型选择器勾选）。

## 性能指标的来源

DSH 的会话日志里，每次模型往返由一对 `step/start` 与 `assistant/message` 界定：

| 指标 | 计算方式 |
|---|---|
| 延迟 | `assistant/message.time - step/start.time` |
| 输出速度 | `(outputTokens + reasoningTokens) / 延迟秒数` |
| 工具耗时 | `tool/result.time - tool/call.time`，按 callId 配对 |
| 工具出错 | 结果文本以 `Error` 开头 |
| 推理占比 | `reasoningTokens / 总 tokens` |

日志里缺少 `step/start` 的调用不计入延迟与速度样本（样本数会单独显示），
因此老会话或截断的日志不会把平均值拉偏。

日期轴按**日历补齐**：某天没有调用时该天仍以 0 出现，不会被跳过。否则 x 轴会变成
「有调用的日子」列表，隔一周的两根柱子挨在一起，既读不出真实的节奏，也看不出断层。
模型曲线同样使用这条补齐后的轴，0 值日连成一条贴底的线而不是断开。

## 计价

价格取自 DeepSeek 官方「模型 & 价格」（人民币 / 百万 tokens）：

| 模型系列 | 缓存命中 | 缓存未命中 | 输出 |
|---|---|---|---|
| `deepseek-flash` | 0.02 / 0.04 | 1 / 2 | 4 / 8 |
| `deepseek-v4-pro` | 0.15 / 0.30 | 4.5 / 9 | 13.5 / 27 |

单元格为「空闲 / 高峰」。高峰时段是北京时间工作日 9:00–12:00、14:00–18:00，其余时段五折；
每条请求按它自己的时间戳判定档位，表里高峰行标 ▲。

模型名按关键字归档：含 `v4-pro` / `reasoner` 或 `-pro` 归为 pro，含 `flash` / `chat` / `v3`
归为 flash，两类都不匹配的（例如第三方中转的 `qoder-cn/dfmodel`）记为**无价格调用**，
只统计 token、不计入金额。

已知误差：中国法定节假日在官方规则里属于空闲时段，这里按繁忙计价，所以金额是轻微高估；
第三方中转商的真实价格与官方不同，按最接近的官方档位估算。

## 性能与缓存

首次打开会后台扫描全部会话，顶部显示进度，已算出的部分立即可见。折叠结果按会话缓存，
之后打开是即时的；进程内的热会话会在后台增量重读。

折叠结果同时落盘到 `~/.dsh/cache/dsh-token-meter/sessions.json`，重启 DSH 后无需重扫全量
（保存时排除仍活跃的会话，这些会话下次启动会重读）。可用环境变量
`DSH_TOKEN_METER_CACHE` 指向别的位置。

面板每 20 秒静默刷新一次统计；扫描进行中则 900ms 一次，以便进度条跟着走。

## 接口

- `GET /api/dsh-token-meter/stats?range=<all|1|7|30|90>` — 聚合数据，含
  `days`（每日，带 `peakCost` / `offCost`）、`rhythm`（7×24）、`modelSeries`（每模型逐日）、
  `models` / `providers` / `workspaces` / `sessions` 排行、`peaks`、`totals`，
  以及 `performance`（延迟 / 吞吐 / 推理占比 / 中断率 / 工具统计）。
- `GET /api/dsh-token-meter/requests?range=…&status=…&q=…&agent=…&model=…&workspace=…&sort=…&dir=…&page=…&size=…`
  — 逐条请求账本，Host 侧筛选/排序/分页；`format=csv` 导出全部匹配行（带 UTF-8 BOM）。

账本路由保留给 CSV 导出与外部调用；面板本身只用 `stats`。

区间按**北京自然日**计算：`1` 是今天零点起，`7` 是含今天的 7 个日历日，不是滚动的 24 小时窗口。

## 安装与更新

这是一个 bundle 包：Host 半 `index.js` 提供聚合、账本查询与 CSV 路由，Client 半 `client.js`
只注册两个插槽（`sidebar.panellist` 图标、`main` 面板），不向对话区域注入任何内容。

用 `plugin_manager` 的 `install_bundle` 指向本目录即可安装。

> **重启提示**：DSH 会把已加载的 Host 模块留在进程的 ESM 缓存里，所以**安装或更新后
> 需要重启一次 DSH**，Host 半的新代码才会生效；页面本身会自动跟随浏览器模块图更新。

## 已知限制

- 只读取本 profile 的会话；其他 profile 的会话不计入。
- 首次全量扫描的耗时取决于会话数量与大小（近百个会话约几十秒），之后有缓存。
- 单价表写死在 `index.js` 的 `TIERS` 常量里；官方调价后需要更新该表。
- 使用节奏按「周一为 0」的星期索引聚合，跨时区查看时仍以北京时间切分。
- 模型曲线一次最多显示 40 条，超出的模型只出现在排行里。
